# 新手教程 · 把多个平台的产物打包成 1 个文件

> 假设你**完全没接触过**这个项目。跟着做就行，不需要懂 Go，也不需要懂 CI。

---

## 0. 这套东西解决什么问题

你想把工具发给别人，但大家设备不一样：

- Windows 电脑 → 要 `.exe`
- 安卓手机 → 要 `.apk`
- iPhone → 要 `.ipa`
- Mac / Linux → 各要各的

于是你得发 4 个文件、写 4 段说明，还要解释"你该下哪个"。

**这个项目把它们合成 1 个文件：**

```
Tool.exe        ← 只发这一个
```

用户拿到后照着做：

| 他用的设备 | 他要做的 |
|---|---|
| **Windows** | 直接**双击** |
| **安卓** | 文件名改成 `Tool.zip` → 解压 → 装里面的 `android/app.apk` |
| **iPhone** | 文件名改成 `Tool.zip` → 解压 → 拿 `ios/App.ipa` 走签名安装 |
| **Mac / Linux** | 文件名改成 `Tool.zip` → 解压 → 运行对应目录里的程序 |

> **为什么不能"Windows 双击 + 安卓直接装"两全？**
> 一个文件的**第 0 个字节**只能是 `MZ`（exe 的头）或 `PK`（zip 的头）中的一个。
> 这是文件格式规范决定的，改后缀救不了。所以只能让一端享受"零操作"，本项目选了 Windows。

## 1. 先准备"原料"

按下面这张表，把你各个平台编出来的东西准备好：

| 平台 | 需要什么 | 放到哪（相对 `payloads/`） | 必需？ |
|---|---|---|---|
| Windows | 主程序 `.exe` | `windows/app.exe` | ✅ **必需** |
| 安卓 | 安装包 `.apk` | `android/app.apk` | 可选 |
| iOS | 安装包 `.ipa` | `ios/App.ipa` | 可选 |
| macOS | `.dmg` / `.pkg` / `.zip` | `mac/App.dmg` | 可选 |
| Linux | AppImage / `.run` / `.deb` | `linux/App.AppImage` | 可选 |

> **Windows 那个是必需的**，因为整包双击后运行的就是它 —— 相当于"发动机"。
> 其余平台没有就跳过，包照样能打。

⚠️ 注意几个**不能直接用**的东西（向导会帮你拦下来）：

- **AAB**（App Bundle）—— 那是给应用商店的，得先用 `bundletool` 转成 APK
- **XAPK / APKS** —— 里面装着好几个 apk 的分卷包，不是单个安装包

## 2. 最快上手：跑向导（推荐）

打开 Termux，两行命令：

```bash
cd ~/sfx-builder
python3 scripts/wizard.py
```

接下来它会**一个平台一个平台地问你**，比如：

```
── Windows ──  windows/app.exe
   Windows 主程序 —— 整包的"发动机"，双击后运行的就是它
   （必需）
   在本机找到这些候选：
     [1] /storage/emulated/0/Download/你的程序.exe   3.2 MB
   拖入文件 / 粘贴路径 / 输入编号 / 回车跳过 > 
```

三种回答方式，随便挑：

| 你想干嘛 | 怎么答 |
|---|---|
| 手机上有这个文件 | 直接输入候选前面的**编号**（比如 `1`） |
| 文件在别处 | **粘贴完整路径**（电脑上可以直接把文件拖进终端） |
| 这个平台没有 | 直接**回车跳过** |

每选一个，它会当场检查"这文件是不是真的对"：

```
   ✓ PE 可执行文件 · 64 位 · GUI 程序  ·  1.5 MB
```

检查不通过会告诉你原因，比如：

```
   ✗ 校验不通过：这是 AAB（App Bundle），不能直接安装；请用 bundletool 转成 APK
```

全部问完，它给你一张汇总表让你确认，然后**自动打包 + 自动校验**：

```
将要打包：
  ✓ Windows  ← …/你的程序.exe    PE 可执行文件 · 64 位 · GUI 程序
  ✓ 安卓     ← …/你的程序.apk    APK · 137 个条目 · dex 8 个
  - iOS（跳过）

开始打包？(Y/n) > 
  放入 payloads/windows/app.exe
  放入 payloads/android/app.apk

▶ 开始打包
▶ 校验产物
完成 ✔  产物：/data/data/com.termux/files/home/sfx-builder/Tool.exe
```

最后它会问要不要顺手提交到 GitHub —— 想的话按 `y`，不想就直接回车。

**产物在哪？** 就是仓库根目录的 `Tool.exe`。

> 常用参数：
> - `python3 scripts/wizard.py --skip-git` —— 不提示提交
> - `python3 scripts/wizard.py --skip-build` —— 只放文件，先不打包

## 3. 不想用向导：手动三步

```bash
cd ~/sfx-builder

# ① 把产物放进去（文件名要对上）
cp 你的程序.exe  payloads/windows/app.exe
cp 你的程序.apk  payloads/android/app.apk
cp 你的程序.ipa  payloads/ios/App.ipa

# ② 打包
bash scripts/build.sh          # 生成 Tool.exe
python3 scripts/verify.py Tool.exe    # 检查产物对不对

# ③ 提交
git add -A
git commit -m "chore: 加入各平台产物"
git push
```

`build.sh` 跑起来长这样：

```
==> 1/3 编译 Windows 引导程序 (GOOS=windows GOARCH=386)
==> 2/3 打包负载 (payloads -> build/payload.zip)
    负载文件数：2
==> 3/3 拼接单文件 Tool.exe

完成：Tool.exe  (2837588 字节)
```

## 4. 让 GitHub 自动打包

`git push` 之后，GitHub 会自动跑一遍验证和打包，**你不用在电脑/手机上做任何事**。

### 去哪看结果

1. 打开 https://github.com/LinXiNexus/sfx-builder/actions
2. 点最上面那条运行记录
3. 页面上有三个 job：

| job | 作用 |
|---|---|
| **打包单文件** | 真正打包 + 校验（`payloads/` 空的时候会自动跳过，不会报错） |
| **冒烟测试（构建）** | 造一个假程序，验证打包流程本身没坏 |
| **冒烟测试（Windows 实跑）** | 在真实的 Windows 机器上运行生成的包，确认"双击→解压→启动"真的能跑 |

4. 页面**最下方**有 `Artifacts` 区域，点 **single-file-package** 就能下载打包好的 `Tool.exe`（保留 14 天）

### 正式发版（打 tag）

```bash
git tag v1.0.0
git push --tags
```

打完 tag，GitHub 会**自动创建 Release**，并附上 `Tool.exe` 和 `Tool.exe.sha256`（校验和）。

查看地址：https://github.com/LinXiNexus/sfx-builder/releases

## 5. 用户拿到包之后怎么用

这段可以直接复制给你的用户 👇

```
【XX 工具 使用说明】
本文件是一个多平台合并包（文件名：Tool.exe）

■ Windows
  直接双击运行。
  若提示"未知发布者 / Windows 已保护你的电脑"，点"更多信息 → 仍要运行"。

■ 安卓
  1) 把文件名 Tool.exe 改成 Tool.zip
  2) 用 ZArchiver / MT管理器 / RAR 打开并解压
     （部分手机自带文件管理器打不开这种包，请用上面推荐的 App）
  3) 安装解压出来的 android/app.apk

■ iPhone / iPad
  1) 改名 Tool.zip 解压，取出 ios/App.ipa
  2) 用 AltStore / Sideloadly 安装，或访问我们的 TestFlight / 签名安装链接
     （iOS 不允许直接安装未签名 IPA，这一步省不掉）

■ macOS / Linux
  改名 Tool.zip 解压，运行对应目录里的程序

校验和（SHA256）见发布页同名 .sha256 文件。
```

> 这段说明会自动打进包里（就是包内那个 `使用说明.txt`），同时建议你在聊天/网页里也发一份。
> 想改内容 → 编辑仓库根目录的 `使用说明.txt`。

## 6. 出问题怎么办

### 向导说"校验不通过"

看它给的原因，对症下药：

| 提示 | 原因 | 怎么办 |
|---|---|---|
| `不是 PE 文件（开头应为 MZ）` | 选错文件了，或者那是脚本不是编译产物 | 换成真正的 `.exe` |
| `根目录没有 AndroidManifest.xml` | 不是 APK（可能是 zip 或分卷包） | 换成单个 `.apk` |
| `这是 AAB（App Bundle）` | AAB 装不了 | 用 `bundletool` 转成 APK |
| `这是分卷安装包（内含 N 个 apk）` | 是 XAPK/APKS | 找单个 `.apk` |

### CI 红了

点进红色的 job 看日志：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `✗ payloads/ 里没有任何产物文件` | 没放产物 | 正常，放进去就好 |
| `缺少 go` / `缺少 zip` | 本地环境缺工具 | Termux：`pkg install golang zip` |
| 冒烟测试红了 | 打包脚本被改坏了 | 看是哪个步骤红的，那一步就是问题所在 |

### 用户说"双击没反应"

让他在命令行跑：

```bat
Tool.exe --sfx-extract D:\out
```

这个命令**只解压不运行**，用来确认包是不是完整的。

- 能解压出文件 → 说明包没问题，多半是杀软拦截了运行
- 解压报错 → 包在传输中损坏了，让他重新下载并核对 `.sha256`

### 杀软 / SmartScreen 报毒

自解压包天然容易被误报。可以做的是：

- 给**内层**的 `app.exe` 做代码签名
- ⚠️ **不要**用 signtool 签最终产物 —— Authenticode 签名会追加到文件末尾，把尾部的 zip 结构破坏掉

### 文件太大，推不上 GitHub

GitHub 单个文件**上限 100 MB**。两个办法：

1. 按平台拆包，只发体积小的（比如只发安卓 + Windows）
2. 让 CI 从别的仓库拉产物：`payloads/` 里别放文件，改用
   `.github/workflows/build.yml` 里注释掉的 `download-artifact` 那一段

## 7. 名词表

| 名词 | 意思 |
|---|---|
| **母体 / SFX** | 这个"一个文件"本体是个 exe（自解压包） |
| **stub（引导程序）** | 里面那个小程序，负责找到负载、解压、启动入口 |
| **payload（负载）** | 你的各平台产物，被塞在文件尾部 |
| **marker** | stub 和负载之间的分隔标记，用来定位负载起点 |
| **ENTRY** | Windows 端解压后要运行哪个文件，默认 `windows/app.exe` |
| **OUT_NAME** | 产物文件名，默认 `Tool.exe` |
| **tag** | Git 的版本标记，打上 `v1.0.0` 并推送就会自动发 Release |

---

## 8. 想改点什么

| 想改什么 | 改哪里 |
|---|---|
| 产物文件名（Tool.exe） | `.github/workflows/build.yml` 里的 `OUT_NAME`；本地用 `OUT_NAME=xxx bash scripts/build.sh` |
| 32 位 / 64 位引导程序 | `STUB_ARCH`（默认 `386`，32/64 位 Windows 通吃） |
| 双击后运行哪个程序 | `ENTRY`（默认 `windows/app.exe`） |
| 用户看到的说明文档 | 仓库根目录 `使用说明.txt` |
| 让 CI 从别的仓库拉产物 | `build.yml` 里注释掉的 `download-artifact` 段 |
| 支持更多平台 | `scripts/wizard.py` 顶部的 `PLATFORMS` 列表 |
